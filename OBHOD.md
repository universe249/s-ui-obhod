# s-ui (obhod)

Форк [alireza0/s-ui](https://github.com/alireza0/s-ui) v1.6.7 с режимом устройств. Интерфейс — alireza0/s-ui-frontend@f473aeb
с правками (вкладка «Устройства», поле «Лимит устройств»), лежит в `frontend/` (без подмодуля).

- `deviceLimit` у клиента: 0 — как в оригинале (общий ключ); N > 0 — подписку получают только приложения,
  присылающие `x-hwid` (Happ, v2RayTun и др.), не больше N устройств.
- У каждого устройства свои ключи (пользователь ядра `<клиент>~d<id>`); общий ключ клиента в ядро не попадает.
  Shadowsocks 2022, ShadowTLS и Snell остаются общими (ключ строгого формата).
- Удаление устройства сразу отключает его ключи и рвёт текущие соединения.
- Смена ключей: по кнопке/API (`deviceRotate`) или автоматически при скачивании подписки раз в
  `deviceRotateHours` часов; прежние ключи работают ещё `deviceGraceHours` часов.
- Лимит превышен или нет `x-hwid` — вместо серверов строка-подсказка и заголовки
  `x-hwid-max-devices-reached`, `x-hwid-limit`, `x-hwid-not-supported` (как у Remnawave).
- Трафик устройств идёт в счёт клиента.

- Журнал устройств (добавлено, удалено, ключи сменены, попытка сверх лимита, приложение без ID) с моделью,
  приложением и адресом; трафик и текущие соединения (с адресами) по каждому устройству.
- Уведомления: `deviceWebhook` + `deviceWebhookSecret` — JSON о каждом событии (заголовок `X-Obhod-Secret`).
- Интерфейс: колонка «Устройства n/лимит» и значок попыток сверх лимита за сутки, фильтр по ним,
  вкладка «Устройства» с журналом, раздел настроек смены ключей и уведомлений.

- Публичный адрес сервера (`publicHost`, Настройки → Подписка): подставляется во все ссылки вместо адреса,
  с которого открыта панель; при изменении ссылки клиентов пересобираются.
- Проверка совместимости входящих: «Allow Insecure», VLESS без шифрования, самоподписанный сертификат, IP или
  чужое имя вместо имени сертификата, истекающий сертификат — значок на карточке входящего и сводка на главной.
- Сроки сертификатов TLS-шаблонов на странице TLS; за 14 дней — уведомление `kind: cert` на адрес уведомлений.

- Секретные адреса подписок: у клиента `subToken`, подписка `/<путь>/<subToken>`; по имени — пока включено
  `subByName` (по умолчанию да; выключить, когда все перешли). Бот берёт токен из `clientInfo`.
- Вход в панель с кодом из Telegram (`login2fa`): после пароля код уходит боту (`kind: login_code`).
  Выключить по SSH: `s-ui setting -login2fa false`. Уведомления о входах и блокировке входа (`login`, `login_locked`).
- Неудачное сохранение, успевшее поменять работающее ядро (например, порт занят), — ядро пересобирается из базы
  (`core_resync`); ядро не поднялось с новым общим конфигом — возвращается прежний (`core_rollback`);
  ядро не работает дольше минуты — `core_down`, поднялось — `core_up`.
- Копия базы каждую ночь в `db/backups` (7 последних, без статистики); `migrate` сначала копирует базу в `*.before-migrate`.

- Переходный период режима устройств: после включения лимита (0 → N) ещё `deviceTransitionHours` часов (по умолчанию 72)
  работает и прежний общий ключ, а приложения без x-hwid или сверх лимита получают подписку как раньше. Трафик по общему
  ключу отмечается (`legacySeenAt`); за сутки до конца — событие `legacy` (бот напоминает обновить подписку), в конце —
  общий ключ убирается из ядра, его соединения рвутся, событие `grace_end`. 0 часов — без периода.

API (`/api` и `/apiv2`): `GET inboundChecks`, `GET certs`, `GET clientInfo?name=<имя>` (клиент + устройства + журнал одним ответом),
`GET deviceSummary`, `GET deviceEvents?c=<id>&n=<сколько>`, `GET devices?c=<id>`, `POST deviceDel ids=1,2`, `POST deviceRotate c=<id|0> grace=<часы>`,
`POST deviceLimit c=<id> limit=<0..100>`.

Сборка: `(cd frontend && npm ci && npm run build) && cp -R frontend/dist/* web/html/`, затем
`. ./build-tags.sh; go build -tags "$(tags_for test),netgo,osusergo" -ldflags "-s -w $(ldflags_for test) -linkmode external -extldflags -static" -o s-ui .`
